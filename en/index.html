A few systems I designed, explained the way I would in a technical interview: the goal, the solution design and the decisions that made a difference.

01 · Dadus Fábrica de Software

Data Warehouse from scratch for the auto parts ERP

Give BI its own analytical database, separate from the ERP’s transactional database, with data refreshed incrementally.

Decisions that mattered

  • Star schema (facts and dimensions): analytical queries that are simple to write and fast to run.
  • Watermark-based incremental loads: each run only processes what changed since the previous one.
  • Queries served through an SQS queue with Redis caching: heavy reports don’t compete with the API for resources, and repeated queries come from the cache.
PostgreSQLPythonAWS SQSRedis

Architecture

  1. ERPtransactional database
  2. Python ETLwatermark-based incremental loads
  3. Data WarehousePostgreSQL · star schema
  4. AWS SQS queueBI queries
  5. Redis cache
  6. Reports and dashboards
02 · Dadus Fábrica de Software

Heavy reports without blocking the user

Generate PDF and CSV reports asynchronously: the screen stays responsive while the file is being produced.

Decisions that mattered

  • The API only publishes the request to the queue: no request is left waiting for the report.
  • A dedicated Python worker handles the generation, separate from the API.
  • File on S3 and result delivered via Redis: users get the link as soon as the file is ready.
LaravelPythonAWS SQSAWS S3Redis

Architecture

  1. Laravel APIreceives the request and responds right away
  2. AWS SQS queue
  3. Python workergenerates PDF/CSV
  4. AWS S3stores the file
  5. Redisreturns the result
03 · Dadus Fábrica de Software

Single sign-on for ~12 services with an in-house SDK

Centralize the platform’s authentication so no service has to reimplement login and token validation.

Decisions that mattered

  • A single login point (SSO) issuing JWT tokens for every service.
  • A shared PHP SDK that validates tokens against the public keys (JWKS), plugged in as PSR-15 middleware.
  • Each service just installs the SDK: the same authentication everywhere, maintained in one place.
LaravelPHPJWTJWKSPSR-15
